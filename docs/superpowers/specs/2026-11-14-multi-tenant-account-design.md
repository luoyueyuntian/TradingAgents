# 统一账号与多租户切换设计（已确认）

## 已确定的需求

- 登录只输入用户名/邮箱和密码，不再输入租户。
- 一个账号可以加入多个租户。
- 登录后默认进入上一次访问的租户，用户可切换自己加入的租户。
- 历史账号按大小写不敏感的相同邮箱合并为同一个账号；此项已由用户明确选择。

## 现状与影响

`web/user_store.py` 的用户记录同时保存密码、租户和角色，用户名、邮箱仅在租户内唯一。会话只有用户 ID；`web/auth.py` 与 `web/app.py` 从用户记录取得租户及角色。前端登录表单要求租户，顶部用户菜单显示当前租户，但没有成员租户切换。

因此本次必须同步调整存储迁移、登录、会话、中间件、成员管理、个人资料、密码重置、前端状态和租户切换，不能只去掉登录页字段。保留工作区中现有未提交改动。

## 方案与取舍

推荐统一账号与独立成员关系。账号负责凭证、邮箱和昵称，成员关系负责每个租户内的角色与状态。这能准确表达同一人在不同租户拥有不同权限，并保证改密只作用于一个账号。

另一种做法是保留每租户一条完整用户记录，以邮箱关联，切换时更换用户记录。这需要同步多个密码和资料，容易出现凭证与状态不一致，不建议采用。

用户已确认本方案，实施采用下列约定。

## 数据模型

- 账号：稳定账号 ID、全局唯一邮箱和用户名、显示名、密码字段、账号禁用/删除/到期状态、`last_tenant_id`。
- 成员：稳定成员 ID、账号 ID、租户 ID、角色、成员禁用/删除/到期状态、创建与更新时间；账号与租户的组合唯一。
- 会话：归属账号并保存 `active_tenant_id`，避免一次切换改变其他设备当前工作区。切换成功同时更新账号的 `last_tenant_id`，供下一次登录使用。
- 保留旧用户 ID 作为对应成员 ID；保留历史审计记录和业务引用，不把旧业务所有者 ID 直接替换成统一账号 ID。
- 接口中明确区分账号 ID 和成员 ID；当前用于工作区业务的 `currentMemberId` 继续使用成员 ID。

## 认证与默认租户

登录按全局唯一用户名或邮箱定位账号，验证一次密码，随后枚举有效成员关系。用户名不能与其他账号的邮箱形成登录标识歧义。

默认选择有效的 `last_tenant_id`；没有历史或历史成员关系失效时，选择最早加入且可访问的租户，并以租户 ID 作为排序平局规则。不得跳入未加入的租户。

没有任何可访问租户时仍允许账号完成身份认证，返回空租户上下文，并展示“暂无可访问租户，请联系管理员”；允许读取个人资料、改密和退出，业务接口返回明确的无租户错误。

每次业务请求重新校验账号、当前成员关系及租户状态，并用当前成员的角色鉴权。客户端传入的租户头不能覆盖会话中的租户。

租户停用、成员移除后仍应允许访问租户列表及切换接口，避免被中间件拦住而无法切到其他有效租户。归档租户保持现有只读规则，是否可访问沿用当前产品规则。

## 接口与界面

- `POST /api/auth/login`：只提交 `identifier`、`password`。
- `GET /api/auth/me`：返回账号资料、当前成员及租户、可访问的成员租户列表、会话到期信息。
- `GET /api/auth/tenants`：返回本人加入且可访问的租户及各租户角色。
- `POST /api/auth/switch-tenant`：提交 `tenant_id`；服务端验证成员资格，事务内更新会话租户和账号最近租户，返回完整会话上下文。失败不改变当前上下文。
- 成员管理支持将已有账号按邮箱加入当前租户并指定角色；账号不存在时创建账号及成员。重复加入返回冲突；加入已有账号不重置其密码或修改账号资料。
- 当前租户管理员仅可管理本租户成员角色、状态与移除；移除成员不删除统一账号和其他租户成员关系。继续保护租户最后一名有效管理员。
- 租户成员管理员不得借成员管理修改统一账号邮箱、密码或全局账号状态。改密、邮件验证、账号资料维护按账号本人或现有明确的平台管理权限执行。
- 登录页删除租户输入。顶栏显示当前租户名称，提供可键盘操作的切换选择器；单租户显示当前租户即可，无租户显示空态。
- 切换成功后更新账号/成员/角色状态，回到首页并重新加载工作区；清理旧租户缓存、关闭订阅，丢弃切换前尚未完成的旧请求结果。失败保留当前页面并展示错误。
- 强制改密流程保留，切换租户不能绕过该限制。

## 历史迁移

迁移需事务化、可重复执行，并提供迁移前冲突预检与摘要；任何失败整体回滚，禁止部分合并。

1. 按 `trim(email).casefold()` 分组，同邮箱合并为统一账号，各原记录转换为成员，保留各自角色、成员状态和成员 ID。
2. 同组最早创建的记录作为账号资料基准，平局按 ID 排序；合并产生的账号全局禁用、删除、到期状态不能由某一个租户成员的局部状态直接覆盖。原状态保留在对应成员上。
3. 为跨邮箱重名用户名生成确定性的唯一后缀并输出变更清单，用户仍可使用原邮箱登录；同时检查用户名与其他账号邮箱交叉冲突。
4. 真正合并多条历史账号时撤销旧会话与重置令牌，要求通过邮箱重设密码；未配置邮件服务时提供受平台管理权限保护的一次性临时密码交付流程。不能任意挑选某个旧密码后让其他成员继续使用不明凭证。
5. 单记录账号保留密码；旧会话明确失效并重新登录。最近租户可从所属租户或历史最后登录记录初始化。
6. 不从生产数据库读取或输出密码散列、盐、令牌或临时密码到迁移摘要。

## 验收与测试

- 新登录请求不带租户；用户名与邮箱登录正常；错误凭证返回一致错误。
- 多租户账号默认恢复最近租户；首次登录、最近租户失效、全部租户不可用时行为明确。
- 切换成功持久化最近租户；重启/再次登录保持；其他设备现有会话租户不被改变。
- 未加入、已移除、已禁用、已到期的成员关系不能用于访问或切换；切换失败不更新历史。
- 不同租户角色实时生效，旧请求、缓存、页面和订阅不会泄露到新工作区。
- 当前租户停用后仍能切换其他有效租户；无租户时不能访问业务资源。
- 成员新增、角色修改、移除、最后管理员保护及租户统计均使用成员关系；修改一个成员不影响其他租户。
- 合并邮箱大小写与空白差异；不同邮箱重名不误合并；旧业务和审计引用保持；迁移幂等且异常回滚。
- 个人资料、邮件验证、改密、找回密码与会话撤销均按统一账号执行；保持强制改密限制。

## 迁移与恢复操作

上线前可对尚未迁移的认证数据库执行只读预检，输出账号合并分组、成员 ID 和用户名变更，不读取密码字段：

```sh
python -m web.account_admin --db /path/to/auth.db preview-migration
```

服务初始化 schema 时自动在事务中迁移。历史同邮箱多账号合并后，原密码失效，旧会话撤销。可以使用邮箱找回密码接口；未配置 SMTP 时，由有服务主机权限的管理员在本机执行：

```sh
python -m web.account_admin --db /path/to/auth.db recover --email user@example.com
```

该命令仅向当前终端输出一次临时密码，撤销账号所有会话和找回令牌，并要求首次登录改密。临时密码应私下交付本人，不写入工单或迁移摘要。租户管理员页面不再提供共享账号改密入口。

当前保留 `users` 表作为成员关系表，并同步账号共享字段供已有业务读取；`accounts` 是身份凭证和资料的权威来源。新接口同时返回 `account_id` 与 `member_id`，历史业务成员 ID 不变。
